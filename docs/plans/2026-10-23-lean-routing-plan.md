# Lean Toolkit Routing

Created: 2026-10-23

## Confirmed contract

The owner approved these decisions in the planning interview and authorized
implementation: optimize total work per successful task; preserve quality;
keep one provider-neutral skill; retain all 31 models, names, aliases and
`/logic`; change routing before card content; support both file access and
manual provision of instructions; use one method by default; compare blinded
outputs; block regressions in routing, evidence honesty, safeguards or required
artifacts; make no fixed percentage promise. Use one primary model initially,
and qualify findings by the conditions actually tested. No paid or key-bearing
checks without a separate owner-run command. No monolithic duplicate payload.

## Sequence and stop rules

1. Freeze baseline file hashes and a common scenario set before payload edits.
2. Shorten entry; separate explicit-name index, selection and combinations.
3. Verify every card remains byte-identical. Exercise named/alias/automatic,
   boundary, logic, combination, missing-input and ordinary-request cases.
4. Compare instruction footprint and blinded answers separately. Static size
   is not total token consumption, latency, or proof of behavioral equivalence.
5. Retain the simplest tested design. Change cards only if evidence demonstrates
   a remaining need. Three-card compression is conditional, not mandatory.
6. Check packaging, clean installation, verified-update protocol (using a local
   test double, not a claim of release verification), rollback and docs.
7. Review and open a PR. Merging changes instruction code and needs owner approval;
   release publication and installation into agents are separate actions.

## Acceptance

All 31 models have a unique index row and category selection route; existing
aliases remain resolvable; critical contracts are traceable in the preservation
map. Required checks pass. All observations state their scope and limitations.
Any material quality regression is fixed or blocks acceptance. Total-spend and
cross-provider claims require evidence beyond instruction-footprint counts.

## Verification surfaces

- `tests/test_validate_skill.py`: routing reachability, alias collisions and
  the existing content/distribution invariants.
- `tests/test_release_tools.py`: deterministic archive, installed file bytes,
  nested guides after update, and recoverable rollback.
- `docs/evaluation/routing-cases.json`: task prompts and acceptance rubric.
- `scripts/measure_context.py`: reproducible static route footprint.
- `docs/evaluation/results.md`: actual observations and unresolved limitations.
