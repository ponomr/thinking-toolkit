# First Principles

**Category:** Problem solving
**Also known as:** Reasoning from first principles, fundamental-truth reasoning

## Purpose

Separate fundamental facts and constraints from assumptions, conventions, and
analogies, then construct a solution from the fundamentals rather than copying
an inherited form.

## Use When

- Existing solutions are expensive, stagnant, or constrained by convention.
- The user suspects the problem statement contains hidden assumptions.
- Analogy produces incremental improvements but not a satisfactory answer.
- A complex problem can be decomposed into essential functions and constraints.

## Avoid When

- A mature standard exists because of hard-won safety or compliance knowledge.
- Time and stakes favor a proven procedure over reinvention.
- The necessary domain expertise or evidence is unavailable.
- "Fundamental truth" would merely rename a strong opinion.

## Inputs

- A precise problem, desired outcome, and scope.
- Current assumptions, conventions, constraints, and solution form.
- Reliable domain facts, physical or logical limits, and stakeholder needs.
- A way to validate both the decomposition and rebuilt solution.

## Procedure

1. State the problem without embedding the current solution.
2. List everything believed to be true about the problem.
3. Classify each statement as verified fact, hard constraint, definition, user
   need, convention, analogy, assumption, estimate, or preference.
4. Challenge non-fundamental statements using repeated why questions and
   disciplined Socratic prompts about meaning, evidence, alternatives,
   implications, and the question itself.
5. Reduce the problem to essential outcomes, functions, resources, and limits.
6. Rebuild several solution approaches from those fundamentals.
7. Reintroduce practical constraints deliberately rather than unconsciously.
8. Compare the rebuilt approaches with the existing solution and test the most
   important novel assumption.

## Guiding Questions

- What must be true, and how do we know?
- Which constraint is physical, logical, ethical, or legal, and which is merely
  conventional?
- What essential outcome does the current solution serve?
- What could we assume instead?
- What evidence would overturn this supposed fundamental?
- If no existing solution existed, what functions would still be necessary?
- What new approach becomes possible after removing an assumption?

## Output Format

| Statement | Type | Evidence | Keep, challenge, or test |
|---|---|---|---|
|  |  |  |  |

Then provide essential outcomes, true constraints, rebuilt solution approaches,
reintroduced practical constraints, and the next validation step.

## Worked Example

A company assumes customer training requires live weekly webinars. Decomposition
shows the fundamentals are accurate instruction, practice, feedback, and proof
of readiness; live scheduling is a convention, not a fundamental. Rebuilding
from those needs produces self-paced scenarios with asynchronous review and
optional live office hours. A pilot tests completion quality before the team
replaces the current program.

## Common Pitfalls

- Calling an assumption a fact because it is widely repeated.
- Ignoring domain standards without understanding why they exist.
- Decomposing so far that human behavior and implementation disappear.
- Assuming first-principles reasoning guarantees novelty or correctness.
- Rebuilding one solution instead of exploring alternatives.
- Failing to test the new assumptions introduced during reconstruction.

## Useful Combinations

- **Abstraction Laddering** — remove solution bias from the problem frame.
- **Zwicky Box** — recombine fundamental functions into novel concepts.
- **Inversion** — reveal hidden constraints and failure conditions.
- **Decision Matrix** — compare rebuilt approaches after validation criteria exist.
- **`/logic` analysis** — test whether a challenged premise is question-begging
  or merely conventional.
