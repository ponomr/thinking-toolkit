# Eisenhower Matrix

**Category:** Decision making
**Also known as:** Urgent-important matrix, priority matrix

## Purpose

Prioritize tasks by separating urgency from importance. Protect important work
from being crowded out by immediate but low-value demands.

## Use When

- A person or team has an overloaded task list.
- Deadlines and interruptions are dominating long-term work.
- The user needs to decide what to do, schedule, delegate, or stop.
- Tasks can be judged against a defined role, goal, or responsibility.

## Avoid When

- Initiatives must be compared by impact and resource cost rather than urgency.
- Options require several weighted criteria.
- Every item is a project that must first be decomposed into actionable tasks.
- Legal, safety, or ethical obligations make prioritization non-discretionary.

## Inputs

- A bounded list of tasks at roughly comparable granularity.
- The goals or responsibilities that define importance.
- Real deadlines, dependencies, and consequences that define urgency.
- Delegation authority, capacity, and relevant owners.

## Procedure

1. Clarify the planning horizon: today, this week, or a larger review period.
2. Define importance as contribution to goals, obligations, or material risk.
3. Define urgency as a genuine time constraint or cost of delay.
4. Classify every task independently on both dimensions.
5. Assign an action by quadrant:
   - important and urgent: do promptly;
   - important and not urgent: schedule protected time;
   - urgent and not important: delegate, automate, or constrain;
   - not urgent and not important: eliminate or deliberately defer.
6. Check capacity. Move scheduled work into real calendar or workflow slots.
7. Record an owner and handoff condition for delegated work.
8. Review recurring urgent items for an upstream prevention opportunity.

## Guiding Questions

- Which goal, responsibility, or risk makes this important?
- What specific deadline or consequence makes this urgent?
- Is the urgency real, inherited from someone else, or self-created?
- What happens if this waits until the next review period?
- Am I the necessary owner? What would safe delegation require?
- Which important work prevents future crises?

## Output Format

| Quadrant | Task | Reason | Action | Owner | Due or review date |
|---|---|---|---|---|---|
| Important and urgent |  |  | Do |  |  |
| Important, not urgent |  |  | Schedule |  |  |
| Urgent, not important |  |  | Delegate or constrain |  |  |
| Neither |  |  | Eliminate or defer |  |  |

Add a short capacity note and identify one recurring urgency to prevent.

## Worked Example

A manager lists a production incident, quarterly hiring plan, routine meeting
request, and unscheduled social media review. The incident is important and
urgent, so the manager handles containment. Hiring is important but not urgent,
so two protected planning blocks are scheduled. The meeting request is urgent
to its organizer but not important to the manager's goals, so a delegate attends
with a clear brief. The social media review is neither and is removed.

## Common Pitfalls

- Calling every visible request urgent.
- Defining importance by emotional pressure rather than goals and obligations.
- Delegating accountability without authority, context, or follow-up.
- Filling the schedule without checking actual capacity.
- Ignoring prevention and allowing important work to become tomorrow's crisis.
- Using the matrix as a one-time cleanup instead of a recurring review.

## Useful Combinations

- **Impact-Effort Matrix** — prioritize within the important backlog.
- **Issue Trees** — break large projects into classifiable actions.
- **OODA Loop** — update priorities when conditions change rapidly.
- **Inversion** — identify important preventive work before a crisis occurs.
