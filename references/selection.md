# Choose a Model

Read this only when the user asks the toolkit to choose a method. Identify the
job and dominant uncertainty, then read the relevant group below. Load only the
chosen card; use the [index](catalog.md) if a name or alias needs resolution.
Select by the desired artifact, using the narrowest method that completes it.
If jobs cross categories, follow the dominant output; consult another group
only if the distinction could change the choice. Explain the choice in one or
two sentences. Start with one model.

| Desired job or artifact | Read |
|---|---|
| Compare options, prioritize, choose effort or response, plan backward, trace consequences | [Decision making](selection/decision-making.md) |
| Diagnose, decompose, reframe, estimate, generate, challenge, resolve opposing demands, review an episode | [Problem solving](selection/problem-solving.md) |
| Map causal dynamics, recurring structures, feedback, or semantic relationships | [Systems thinking](selection/systems-thinking.md) |
| Draft behavior-based feedback or communicate a supported conclusion | [Communication](selection/communication.md) |

Audit existing reasoning only on an explicit `/logic` request: use
[logic overview](../logic/overview.md). If such a request accompanies a model
request, keep their outputs distinct. A communication method needs adequate
underlying analysis; when evidence is missing, expose the gap rather than
making a polished unsupported claim.
